# DECISIONS LOG

Append-only. One line per judgment call: what was chosen, why, what would change it. Newest at the bottom.

- 2026-07-31 | `git init` locally with `main` + branch-per-item, local `--no-ff` merges standing in for PRs | repo had no git and no remote; CLAUDE.md requires branch/PR flow | a GitHub remote (see NEEDS-USER.md) switches merges to real PRs.
- 2026-07-31 | Bootstrap research on providers done via web against official docs, with an adversarial verify pass, before writing architecture.md | repo contains zero credentials/docs, and CLAUDE.md forbids guessing provider capabilities | actual credentials or vendor docs landing in the repo supersede web findings.
- 2026-07-31 | Roadmap orders Meta spike (desk portion) and a1mobile audit before any scaffolding | both integrations shape adapter contracts and the escalation flow; CLAUDE.md calls the glasses the least-known capability | hardware + toolkit access arriving early would let the spike include device verification instead of desk-only.
- 2026-07-31 | pnpm workspaces chosen for the monorepo (pending install; Node 22 present) | PRD suggests TS monorepo; pnpm is the current standard for workspace monorepos and Node 22 ships corepack | if corepack/pnpm proves troublesome on this machine, fall back to npm workspaces.
- 2026-07-31 | **Will not call a1mobile's undocumented internal API** (`api.a1mobile.com/api/v1/*`, discovered in their dashboard's public JS bundles) | undocumented, auth-gated, no contractual stability; violates CLAUDE.md's integration rule and near-certainly a1mobile's terms | a1mobile publishing real docs and issuing us credentials — nothing less.
- 2026-07-31 | **No further probing of a1mobile's live endpoints.** The research pass issued unauthenticated requests to api.a1mobile.com before this rule existed; it's recorded in architecture.md §2.3 and stops there | probing a third party's auth-gated service is not research against public docs | nothing; further a1mobile questions get asked of a1mobile.
- 2026-07-31 | A1MobileAdapter contract specified against the **union of Twilio Programmable Voice + Telnyx Call Control** public docs, with every a1mobile capability marked `pending` | a1mobile publishes no contract to build against; any telephony provider must satisfy roughly this shape, and referencing public vendor docs to design our own interface asserts no a1mobile endpoint | real a1mobile docs landing, which would replace the reference shape entirely.
- 2026-07-31 | Domain layer models the **async command/webhook shape (Telnyx-style), not synchronous TwiML request-response** | Cynthia's hold-ask-founder-relay flow is inherently asynchronous and multi-turn; letting TwiML's request-response shape into the domain would make the core flow fight the abstraction | nothing foreseeable; a TwiML adapter translates downward (hold → `<Enqueue>`, resume → REST update).
- 2026-07-31 | Idempotency keys derive from **provider event ID as an opaque string** extracted by a per-provider mapper, never from payload content | Twilio `CallSid`/`MessageSid` and Telnyx event `id` are the natural keys; a1mobile's field name is unknown, and content-hashing would break legitimate retries with mutated payloads | a provider that genuinely emits no stable event ID, which would force a content-plus-window fallback.
- 2026-07-31 | MetaWearableAdapter's server-side contract **terminates at the companion app**, emitting device-agnostic domain events | DAT has no server API and no cloud-to-glasses push — everything is phone-mediated over Bluetooth; identical events from glasses, companion app, web inbox or simulator are what make the simulator honest | Meta shipping a server-side API, which does not exist today.
- 2026-07-31 | Native companion app is **out of the TS monorepo's vertical slice**; glasses leg proven through simulator + web inbox | DAT is native iOS/Android only (no React Native), and we have no Meta account, no hardware, and no Xcode | any of those three arriving, at which point the spike's device half runs for real.
- 2026-07-31 | Escalation requires **positive delivery confirmation**; absent an ack, degrade push → web inbox → honest client deferral | background _initiation_ of glasses audio is unproven (architecture.md §3.3), and CLAUDE.md forbids ever treating silence as a founder answer | nothing — this holds even if the glasses path proves fully reliable.
- 2026-07-31 | Supabase RLS membership via a **`security definer` lookup function**, not JWT `app_metadata` claims | Supabase docs state plainly that "a JWT is not always fresh"; org membership can change mid-session and stale claims would silently mis-scope tenant data | membership becoming immutable per session, which it isn't.
- 2026-07-31 | Realtime channels topic-shaped `org:<organization_id>` with private channels + RLS on `realtime.messages` | reuses the same membership tables as row RLS, so realtime authorization can't drift from row authorization | none; `postgres_changes` stays acceptable at MVP scale but this is the documented scalable pattern.
- 2026-07-31 | **pgvector deferred until plain search is shown insufficient** on the seed knowledge set, with the comparison logged either way | CLAUDE.md scopes pgvector to "where semantic retrieval actually improves knowledge search" — that's a measurement, not an assumption | seed-set retrieval measurably missing paraphrased questions, which is the likely outcome and fine to act on once shown.
- 2026-07-31 | **DAT treated as optional for the MVP, not foundational** — the escalation flow is specified against plain Bluetooth audio, with DAT as later polish | DAT exposes no audio API at all, and Cynthia's flow is audio-only; if experiment E1 confirms audio needs no session, DAT leaves the critical path entirely | E1 showing a DAT session _is_ required for A2DP/HFP, which would pull the whole registration/permission/review path back onto the critical path.
- 2026-07-31 | **iOS hands-free prompting scoped to "founder opts into an availability session first"** rather than promised from cold | three documented iOS blockers (throttled silent push, `cannotInterruptOthers` on background activation, PushKit requires CallKit); PushToTalk is the only sanctioned mechanism and it needs a pre-joined channel | Apple granting a PushToTalk entitlement and PTT audio routing to A2DP proving out (experiment E5), or Apple changing background-audio policy.
- 2026-07-31 | **Android-first for hands-free delivery; no iOS parity promised at launch** | Android has a complete documented chain (high-priority FCM → FGS background-start exemption → connectedDevice/mediaPlayback → A2DP); iOS has none | E5 succeeding, or the founder's own device being iOS and hands-free being non-negotiable — in which case the availability-session shape is the answer, not parity.
- 2026-07-31 | **Fallback ladder promoted from defensive padding to primary design**: glasses → companion push → web inbox → honest deferral, each rung needing a positive ack | hands-free delivery is unproven on Android and unsupported-as-designed on iOS, so the ladder is the load-bearing path rather than an edge case | nothing — CLAUDE.md forbids treating silence as an answer regardless of how reliable delivery becomes.
- 2026-07-31 | **Escalation expiry owned by the orchestrator's timer, never the device or adapter** | a dead or backgrounded adapter must not be able to stall an escalation past its deadline; the client is owed a deferral on schedule | nothing foreseeable.
- 2026-07-31 | **`transcriptionConfidence` mandatory on every founder `answered` event** | HFP capture is 8 kHz narrowband and CLAUDE.md requires confirming critical names/dates/prices when confidence is low — the adapter must surface it so the orchestrator can gate | a capture path with confidence high enough to be uninteresting, which narrowband Bluetooth will not provide.
- 2026-07-31 | **Spike sourcing rule: only wearables.developer.meta.com, github.com/facebook/meta-wearables-dat-\*, developers.meta.com, and first-party Apple/Android docs count as evidence** | an unofficial gist introduced a phantom `audioStreamingError` case using pre-0.7 type names that contradicts the shipping 0.8 `StreamError` | nothing; the rule stays.
- 2026-07-31 | **TypeScript pinned to 6.0.3, not 7.x** | TS 7 (Go port) is GA and much faster, but `typescript-eslint@8.65.0` peers on `typescript >=4.8.4 <6.1.0` and aborts on TS 7 — verified against the registry — which would silently cost all type-aware linting | TS 7.1 shipping the stable programmatic compiler API (~Oct 2026), or typescript-eslint adding tsgo support.
- 2026-07-31 | pnpm installed via **Homebrew**, not corepack | `corepack enable` cannot write shims to /usr/local without sudo on this machine, and Node 26 drops corepack entirely — installing pnpm directly is now the recommended path | nothing; `devEngines.packageManager` handles version pinning from here.
- 2026-07-31 | **`packages/domain` purity enforced by ESLint**, not convention: `node:*`/fs/http imports, `new Date()`, `Math.random()`, and `@supabase/*` are lint errors there | CLAUDE.md makes determinism an architecture invariant, and a rule a reviewer has to remember is a rule that erodes; verified the guard actually fires | nothing — if the domain genuinely needs time or randomness, it gets injected.
- 2026-07-31 | Vitest discovers tests **only under `src/`** | `tsc --build` also emits compiled `.test.js` into dist, which made every test run twice; worse, a stale dist could pass while source was broken | moving tests out of the emitting project entirely, which would cost a second tsconfig per package for no current benefit.
- 2026-07-31 | Tests stay inside each package's composite tsconfig, so **test files are typechecked** and compiled copies land in dist | typechecking tests matters more than dist tidiness, and nothing here is published (`private: true`) | publishing any package, at which point tests move to a separate non-emitting project.
- 2026-07-31 | Workspace packages export a **`cynthia:source` condition → `src/`**, with `default` → `dist/` | tests and typecheck read TypeScript directly with no build step, while plain Node still gets built output; Node refuses to strip types under node_modules, so source-only exports break on deploy/publish | nothing; this is the verified-working shape.
- 2026-07-31 | **CLAUDE.md and docs/PRD.md excluded from Prettier** | they are the user's authored source-of-truth specs; formatting them churned bullet markers and would re-churn every time an updated version is pasted in | nothing.
- 2026-07-31 | `apps/web` scaffolded as a plain TS package; **Vite/React deferred to roadmap 6.1** | 2.1's job is the toolchain harness, and committing to a frontend stack before there is a UI to build is scope the roadmap already places in phase 6 | starting 6.1, which adds the real stack.
- 2026-07-31 | State machine is **event-driven** (`state × event → state`) rather than raw state-to-state | the audit trail has to record _why_ a transition happened, not just that it did; an event name is the reason | nothing.
- 2026-07-31 | `transition()` **returns a result, never throws** on an invalid transition | an exception unwinding through the orchestrator is exactly how a client ends up in unexplained silence; forcing the caller to handle rejection keeps CLAUDE.md's "never left in silence" rule enforceable | nothing.
- 2026-07-31 | **`DEFERRED` is only reachable from `ESCALATION_PENDING`, `FOUNDER_PROMPTED`, `FOUNDER_RESPONDED`, `HANDOFF`, or `FAILED`** | you should not be able to defer without having actually tried to reach the founder or having hit a failure; making it structurally impossible beats a code-review rule | a genuine product need to defer without attempting escalation (e.g. an explicit founder "do not disturb"), which would still route through ESCALATION_PENDING → DEFERRED rather than adding a shortcut.
- 2026-07-31 | **`RELAYING` means relaying a _founder_ answer specifically**; a direct knowledge answer goes `RESOLVING → RESOLVED` without passing through it | matches the PRD's flow description and keeps the audit timeline unambiguous about whether a human was involved in any given answer | nothing.
- 2026-07-31 | `RESOLVED`, `DEFERRED`, and `FAILED` are **not terminal** — only `ENDED` is; each still needs `CONVERSATION_ENDED` | the call is still connected after an answer is delivered, and modelling that honestly is what lets the machine guarantee a client is never stranded | nothing.
- 2026-07-31 | The one-clarification limit lives in **machine context**, not just the transition table | the table alone cannot prevent ACTIVE → CLARIFYING recurring after a loop back; a counter makes it a reachability property the machine owns | nothing.
- 2026-07-31 | `TRANSITIONS` declared with an **explicit `Record` annotation** rather than `as const satisfies` | `as const` gives each state a distinct literal shape, so indexing with a broad event union produced an error type and an unsafe-assignment lint failure; the annotation still enforces that all 13 states are present | needing per-state literal event types, which nothing currently does.
