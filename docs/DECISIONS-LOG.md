- 2026-07-31 | **Escalation expiry owned by the orchestrator's timer, never the device or adapter** | a dead or backgrounded adapter must not be able to stall an escalation past its deadline; the client is owed a deferral on schedule | nothing foreseeable.
- 2026-07-31 | **`transcriptionConfidence` mandatory on every founder `answered` event** | HFP capture is 8 kHz narrowband and CLAUDE.md requires confirming critical names/dates/prices when confidence is low — the adapter must surface it so the orchestrator can gate | a capture path with confidence high enough to be uninteresting, which narrowband Bluetooth will not provide.
- 2026-07-31 | **Spike sourcing rule: only wearables.developer.meta.com, github.com/facebook/meta-wearables-dat-\*, developers.meta.com, and first-party Apple/Android docs count as evidence** | an unofficial gist introduced a phantom `audioStreamingError` case using pre-0.7 type names that contradicts the shipping 0.8 `StreamError` | nothing; the rule stays.
- 2026-07-31 | **TypeScript pinned to 6.0.3, not 7.x** | TS 7 (Go port) is GA and much faster, but `typescript-eslint@8.65.0` peers on `typescript >=4.8.4 <6.1.0` and aborts on TS 7 — verified against the registry — which would silently cost all type-aware linting | TS 7.1 shipping the stable programmatic compiler API (~Oct 2026), or typescript-eslint adding tsgo support.
- 2026-07-31 | pnpm installed via **Homebrew**, not corepack | `corepack enable` cannot write shims to /usr/local without sudo on this machine, and Node 26 drops corepack entirely — installing pnpm directly is now the recommended path | nothing; `devEngines.packageManager` handles version pinning from here.
- 2026-07-31 | **`packages/domain` purity enforced by ESLint**, not convention: `node:*`/fs/http imports, `new Date()`, `Math.random()`, and `@supabase/*` are lint errors there | CLAUDE.md makes determinism an architecture invariant, and a rule a reviewer has to remember is a rule that erodes; verified the guard actually fires | nothing — if the domain genuinely needs time or randomness, it gets injected.
- 2026-07-31 | Vitest discovers tests **only under `src/`** | `tsc --build` also emits compiled `.test.js` into dist, which made every test run twice; worse, a stale dist could pass while source was broken | moving tests out of the emitting project entirely, which would cost a second tsconfig per package for no current benefit.
- 2026-07-31 | Tests stay inside each package's composite tsconfig, so **test files are typechecked** and compiled copies land in dist | typechecking tests matters more than dist tidiness, and nothing here is published (`private: true`) | publishing any package, at which point tests move to a separate non-emitting project.
- 2026-07-31 | Workspace packages export a **`iris:source` condition → `src/`**, with `default` → `dist/` | tests and typecheck read TypeScript directly with no build step, while plain Node still gets built output; Node refuses to strip types under node_modules, so source-only exports break on deploy/publish | nothing; this is the verified-working shape.
- 2026-07-31 | **CLAUDE.md and docs/PRD.md excluded from Prettier** | they are the user's authored source-of-truth specs; formatting them churned bullet markers and would re-churn every time an updated version is pasted in | nothing.
- 2026-07-31 | `apps/web` scaffolded as a plain TS package; **Vite/React deferred to roadmap 6.1** | 2.1's job is the toolchain harness, and committing to a frontend stack before there is a UI to build is scope the roadmap already places in phase 6 | starting 6.1, which adds the real stack.
- 2026-07-31 | State machine is **event-driven** (`state × event → state`) rather than raw state-to-state | the audit trail has to record _why_ a transition happened, not just that it did; an event name is the reason | nothing.
- 2026-07-31 | `transition()` **returns a result, never throws** on an invalid transition | an exception unwinding through the orchestrator is exactly how a client ends up in unexplained silence; forcing the caller to handle rejection keeps CLAUDE.md's "never left in silence" rule enforceable | nothing.
- 2026-07-31 | **`DEFERRED` is only reachable from `ESCALATION_PENDING`, `FOUNDER_PROMPTED`, `FOUNDER_RESPONDED`, `HANDOFF`, or `FAILED`** | you should not be able to defer without having actually tried to reach the founder or having hit a failure; making it structurally impossible beats a code-review rule | a genuine product need to defer without attempting escalation (e.g. an explicit founder "do not disturb"), which would still route through ESCALATION_PENDING → DEFERRED rather than adding a shortcut.
- 2026-07-31 | **`RELAYING` means relaying a _founder_ answer specifically**; a direct knowledge answer goes `RESOLVING → RESOLVED` without passing through it | matches the PRD's flow description and keeps the audit timeline unambiguous about whether a human was involved in any given answer | nothing.
- 2026-07-31 | `RESOLVED`, `DEFERRED`, and `FAILED` are **not terminal** — only `ENDED` is; each still needs `CONVERSATION_ENDED` | the call is still connected after an answer is delivered, and modelling that honestly is what lets the machine guarantee a client is never stranded | nothing.
- 2026-07-31 | The one-clarification limit lives in **machine context**, not just the transition table | the table alone cannot prevent ACTIVE → CLARIFYING recurring after a loop back; a counter makes it a reachability property the machine owns | nothing.
- 2026-07-31 | `TRANSITIONS` declared with an **explicit `Record` annotation** rather than `as const satisfies` | `as const` gives each state a distinct literal shape, so indexing with a broad event union produced an error type and an unsafe-assignment lint failure; the annotation still enforces that all 13 states are present | needing per-state literal event types, which nothing currently does.
- 2026-07-31 | **Two independent idempotency layers**: envelope dedupe (skip repeat deliveries) and deterministic side-effect keys (`<envelopeKey>#<kind>[#discriminator]`) | envelope dedupe only works if the event was durably recorded _before_ any side effect; the side-effect key is what survives a crash mid-flight, a manual replay, or two workers racing | nothing — belt and braces is correct for anything that sends an SMS or books a slot.
- 2026-07-31 | Idempotency key is `provider:providerEventId`, split on the **first** colon | `ProviderId` is a closed union with no colon, so a provider event ID may itself contain colons (URNs) without collision risk | adding a provider whose id contains a colon, which the type system prevents.
- 2026-07-31 | **Out-of-order events are flagged but still processed**, not dropped | dropping a late event risks losing real information (a hangup, a founder answer), whereas acting on an illegal one is already safely rejected by the state machine and recorded as an audit event | evidence that a provider replays stale events in a way the state machine cannot distinguish from live ones.
- 2026-07-31 | **Dedupe takes precedence over ordering** — a duplicate is skipped even when also out of order | processing a duplicate is the more dangerous of the two failures; it is the one that double-sends | nothing.
- 2026-07-31 | An event with a **blank provider event ID is refused outright**, not accepted with a synthesised key | a blank id would collapse every event onto one key and silently discard real traffic; if a provider truly has no stable id, its adapter must synthesise a deterministic one before building an envelope | nothing.
- 2026-07-31 | Side-effect discriminators must be **derived from data, never from a counter or timestamp** (documented on the function) | a counter is not stable across a replay, which silently destroys the guarantee the key exists to provide | nothing.
- 2026-07-31 | **Sensitivity is the first gate**, ahead of sourcing and confidence | being certain about a refund is not authorisation to issue one; if the cheap checks ran first, a well-sourced high-confidence sensitive request could slip through | nothing — this ordering is the scope boundary.
- 2026-07-31 | The domain **refuses to infer handoff from reply text**; only a typed `take-call` signal accepts | CLAUDE.md forbids inferring acceptance from a generic reply, and substring-matching "put them through" is exactly that; mapping an explicit affordance (button/recognised command) onto the signal is the adapter's job | nothing.
- 2026-07-31 | Sensitive-category **classification happens upstream** (AI service); the domain consumes detected categories | classifying natural language is not deterministic and cannot live in a pure package; the gate's job is deciding what to do about a classification, which is the part that must never drift | nothing.
- 2026-07-31 | Knowledge scope is **a property of the knowledge item**, not a retrieval heuristic | "customer-specific information stays scoped to that contact/organization" is only guaranteeable if scope travels with the item; a ranking-time filter can be bypassed by any new retrieval path | nothing.
- 2026-07-31 | A **low-confidence critical detail escalates rather than confirms once the clarification budget is spent** | confirmation is a question to the caller, so it consumes the one-clarification budget; the alternative is unlimited confirmations, which violates the spirit of the limit | evidence that callers experience the single-clarification cap as too tight, which is a product call not an engineering one.
- 2026-07-31 | `DeferralPlan.answerToClient` is typed `null` rather than omitted | it makes "a deferral never carries an answer" visible at the call site rather than implied by absence | nothing.
- 2026-07-31 | Follow-up keys derive from `escalationId`, not from an inbound provider event | a founder timeout is our own timer firing, not something a provider reported, so there is no provider event to key on; one escalation owes at most one follow-up by construction | nothing.
- 2026-07-31 | **Unknown-caller floor implemented as an explicit rule**, applied after scoring, rather than by tuning weights | CLAUDE.md says an unknown caller is never low-priority _only because_ unknown; a weight-based approximation can be quietly retuned into violation, whereas a named floor cannot, and the founder sees the reason string explaining it was applied | nothing.
- 2026-07-31 | Priority thresholds: critical ≥6, high ≥3, normal ≥1, low 0 — so **a VIP with a live deal is `high`, not `critical`** | critical should require urgency or a deeper relationship on top, otherwise it stops meaning anything and every escalation looks maximal | real founder feedback that too much or too little reaches critical; the weights are configuration-shaped and easy to retune.
- 2026-07-31 | Over-long context is **truncated visibly (ellipsis + `contextTruncated` flag)**, not rejected | context is assembled from a live transcript so overshooting the PRD's 40 words is normal, but the founder must be able to tell they are reading an excerpt | nothing.
- 2026-07-31 | `take-call` appears in `allowedActions` **only when a transfer is actually possible** (call not SMS, transfer capability live) | offering an action that cannot be carried out is how a founder ends up accepting a handoff that then fails in front of the client | nothing.
- 2026-07-31 | A packet with a non-positive or non-finite TTL is **refused** | an escalation that never expires is a client on hold forever, which is the exact failure CLAUDE.md forbids | nothing.
- 2026-07-31 | Domain purity lint refined: `new Date(iso)` is **allowed**, `new Date()` and `Date.now()` remain banned | reading the clock is impure, but arithmetic on an injected timestamp is deterministic — the original blanket ban would have forced expiry computation out of the domain for no correctness gain | nothing.
- 2026-07-31 | The **simulator emits signed webhook deliveries that go through `verifyAndParse`**, rather than handing back parsed events | if the simulator bypassed verification and envelope construction, the code exercised in tests would not be the code that runs against a real provider — which is the difference between an honest simulator and a fake | nothing.
- 2026-07-31 | The **production adapter returns a typed `capability-pending` failure instead of throwing** | a thrown "not implemented" surfaces unpredictably; a typed refusal forces the orchestrator to handle it, which is how the client gets an honest deferral rather than silence | credentials arriving, at which point capabilities flip to `live` one at a time and the contract above them does not change.
- 2026-07-31 | Commands return a **`CommandAck` with a provider reference** rather than `void` | the audit timeline needs something to correlate against provider logs months later, and the lint rule against `void` generics was pointing at a real design weakness | nothing.
- 2026-07-31 | Simulator webhook signatures use a **non-cryptographic FNV-1a digest**, documented as such | the point is to exercise the verification code path so a real signing scheme drops in unchanged; using node:crypto would tie the adapters package to Node and break the browser build for `apps/web`, which imports it for capability copy | needing genuine crypto in a simulator, which would mean it is guarding something real — and it never should.
- 2026-07-31 | Out-of-order delivery needs **no special simulator API** — deliveries carry their sequence number and tests feed them in any order | a dedicated "deliver out of order" method would model the reordering rather than the events, and the sequence number is what the domain actually reasons about | nothing.
- 2026-07-31 | The simulator **refuses commands against unknown call ids** | a real provider does too, and silently accepting them would let an orchestrator bug (acting on an ended call) pass tests | nothing.
- 2026-07-31 | **Removed the `expired` variant from the founder-response union** that the spike sketch had included | expiry is the orchestrator's timer firing, not something a device reports; leaving it out means a dead or backgrounded adapter _structurally cannot_ stall an escalation past its deadline, rather than relying on everyone remembering the rule | nothing.
- 2026-07-31 | Two Meta capabilities are **`unsupported`, not `pending`**: server-to-glasses push and custom wake word | pending means "no credentials yet"; these are documented as non-existent, so no access would flip them, and conflating the two would misrepresent what is achievable | Meta shipping a server API or third-party voice invocation, both currently listed as not offered.
- 2026-07-31 | **A successful delivery is memoised but a failed one is not** | a retry must not prompt the founder twice, but the fallback ladder depends on being able to retry a rung that failed — memoising failure would freeze the ladder at its first bad outcome | nothing.
- 2026-07-31 | Responses to **unknown, already-answered, or cancelled escalations are dropped** with a typed rejection | a late founder answer arriving after the client hung up would otherwise land on a conversation that has moved on; the client is gone and the answer is stale | nothing.
- 2026-07-31 | `transcriptionConfidence` is **mandatory on every answer event** | HFP capture is 8 kHz narrowband, and confidence has to reach the policy gate that confirms critical details rather than being dropped at the adapter boundary | nothing.
- 2026-07-31 | **All four dependency-failure obligations fall out of one `planRecovery` call** rather than being four separate steps a caller sequences | CLAUDE.md's failure sentence is four promises, and the realistic failure mode is honouring three and forgetting the fourth; one decision makes partial compliance impossible | nothing.
- 2026-07-31 | **A follow-up is still owed after the client hangs up** — only the `speakToClient` obligation lapses | the thread is not dead because the call dropped; someone has to ring them back, and that is exactly what gets forgotten | nothing.
- 2026-07-31 | Alert severity is **critical when the client was still connected**, warning otherwise | a failure with someone waiting on the line is materially worse than one found after they left, and the founder should see that at a glance rather than triaging identical alerts | nothing.
- 2026-07-31 | **Per-rung idempotency keys** (`<baseKey>#<channel>`) in the fallback ladder | with a shared key, an adapter that had already seen it would report a phantom duplicate and the prompt would silently never be shown on the lower rung — a failure that looks like success | nothing.
- 2026-07-31 | `cancelAcrossLadder` uses `Promise.allSettled` | a rung that throws must not stop the others being told, or a founder answers a question for a client who already hung up | nothing.
- 2026-07-31 | The ladder's **rung order is the caller's choice**, not baked in | preference depends on the founder's availability mode and phone platform — on iOS the glasses rung is unsupported-as-designed, so the orchestrator may skip straight to the inbox | nothing.
- 2026-07-31 | **Everything impure sits behind orchestrator ports**, with in-memory implementations that are the real local-dev implementation rather than stubs | it makes the loop deterministic and fully testable before a database exists, and it unblocked phase 5 while phase 3 waits on a container runtime | nothing; the Supabase implementations satisfy the same contract.
- 2026-07-31 | **Dedupe runs before any state change; the delivery is recorded after the work** | recording first would make a crash mid-handler look like success and drop the event permanently, whereas recording last means a crash replays — and the dedupe check on replay is what stops the double side effect | nothing.
- 2026-07-31 | **A rejected transition still records its delivery** | it was handled and the answer was "no"; leaving it unrecorded would let a provider retry re-attempt the same illegal transition forever | nothing.
- 2026-07-31 | The audit trail has **five record kinds**, not just transitions: accepted, rejected, duplicate-skipped, observed, ingest-rejected | an audit that only shows successes cannot answer "the provider clearly sent us something — why did nothing happen?", which is the question anyone debugging a live call will actually ask | nothing.
- 2026-07-31 | `conversationEventFor` returns `undefined` for transcript segments, SMS statuses and recordings — **a real answer, not a gap** | those carry genuine information but move no state; auditing them as observations keeps the timeline complete without inventing transitions | later phases may map transcript segments to CLARIFICATION_RECEIVED once the resolution module exists.
- 2026-07-31 | The in-memory ledger **never moves a high-water mark backwards** | a late-arriving event must not rewrite how far the conversation had got, or subsequent events would stop being flagged as out-of-order | nothing.
- 2026-07-31 | **D.4 settled by measurement, not preference: plain lexical retrieval ships for the MVP; pgvector is deferred but justified.** Measured on the 8-entry seed set: **8/8 directly-phrased questions correct, 2/8 paraphrases**. Crucially all six paraphrase misses return _no match at all_ rather than the wrong entry, so plain search fails **safely** into escalation | a 6/8 paraphrase miss rate is a real quality problem (callers would escalate far more than necessary) but not a safety one, so it does not block the demo; adopting pgvector needs an embedding provider and a container runtime that do not exist yet | the bake-off test is the baseline to beat — when Docker and embeddings land, semantic retrieval must demonstrably beat 2/8 before being adopted. Cannot empirically compare pgvector today; that is deferred, not assumed.
- 2026-07-31 | **Interrogatives are stopwords** (`how`, `what`, `when`, `where`, `which`, `who`, `why`) | this fixed a real bug the bake-off caught: an entry titled "How to reach us" was the top hit for "how long is the warranty", because "how" appeared in exactly one entry and was therefore scored as highly discriminating. Question words distinguish kinds of _question_, but the knowledge base is a corpus of declarative _answers_, so they encode nothing | a knowledge base that stores questions as well as answers, which would make interrogatives meaningful again.
- 2026-07-31 | **Scope and approval filter before answer composition**, not after | filtering only the reported source list would let a customer-specific entry shape the words spoken while being invisible in the audit trail — the worst of both. Tests assert on the answer _text_, not just the ids | nothing.
- 2026-07-31 | **Ambiguity reduces confidence**: when the runner-up scores ≥85% of the leader, confidence is halved | "I found two equally good answers" is not confidence, and the right response is to escalate rather than pick one; without this the policy gate would happily answer from a coin-flip | tuning the ratio if real traffic shows it firing too often.
- 2026-07-31 | The bake-off measures with the **production score threshold applied** | measuring on `score > 0` counted weak accidental matches as successes and flattered the ranker — it initially reported a paraphrase "hit" that production would have rejected | nothing.
