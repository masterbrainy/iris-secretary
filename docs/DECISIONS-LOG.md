# DECISIONS LOG

Append-only. One line per judgment call: what was chosen, why, what would change it. Newest at the bottom.

- 2026-07-31 | `git init` locally with `main` + branch-per-item, local `--no-ff` merges standing in for PRs | repo had no git and no remote; CLAUDE.md requires branch/PR flow | a GitHub remote (see NEEDS-USER.md) switches merges to real PRs.
- 2026-07-31 | Bootstrap research on providers done via web against official docs, with an adversarial verify pass, before writing architecture.md | repo contains zero credentials/docs, and CLAUDE.md forbids guessing provider capabilities | actual credentials or vendor docs landing in the repo supersede web findings.
- 2026-07-31 | Roadmap orders Meta spike (desk portion) and a1mobile audit before any scaffolding | both integrations shape adapter contracts and the escalation flow; CLAUDE.md calls the glasses the least-known capability | hardware + toolkit access arriving early would let the spike include device verification instead of desk-only.
- 2026-07-31 | pnpm workspaces chosen for the monorepo (pending install; Node 22 present) | PRD suggests TS monorepo; pnpm is the current standard for workspace monorepos and Node 22 ships corepack | if corepack/pnpm proves troublesome on this machine, fall back to npm workspaces.
- 2026-07-31 | **Will not call a1mobile's undocumented internal API** (`api.a1mobile.com/api/v1/*`, discovered in their dashboard's public JS bundles) | undocumented, auth-gated, no contractual stability; violates CLAUDE.md's integration rule and near-certainly a1mobile's terms | a1mobile publishing real docs and issuing us credentials — nothing less.
- 2026-07-31 | **No further probing of a1mobile's live endpoints.** The research pass issued unauthenticated requests to api.a1mobile.com before this rule existed; it's recorded in architecture.md §2.3 and stops there | probing a third party's auth-gated service is not research against public docs | nothing; further a1mobile questions get asked of a1mobile.
- 2026-07-31 | A1MobileAdapter contract specified against the **union of Twilio Programmable Voice + Telnyx Call Control** public docs, with every a1mobile capability marked `pending` | a1mobile publishes no contract to build against; any telephony provider must satisfy roughly this shape, and referencing public vendor docs to design our own interface asserts no a1mobile endpoint | real a1mobile docs landing, which would replace the reference shape entirely.
- 2026-07-31 | Domain layer models the **async command/webhook shape (Telnyx-style), not synchronous TwiML request-response** | Cynthia's hold-ask-founder-relay flow is inherently asynchronous and multi-turn; letting TwiML's request-response shape into the domain would make the core flow fight the abstraction | nothing foreseeable; a TwiML adapter translates downward (hold → `<Enqueue>`, resume → REST update).
- 2026-07-31 | Idempotency keys derive from **provider event ID as an opaque string** extracted by a per-provider mapper, never from payload content | Twilio `CallSid`/`MessageSid` and Telnyx event `id` are the natural keys; a1mobile's field name is unknown, and content-hashing would break legitimate retries with mutated payloads | a provider that genuinely emits no stable event ID, which would force a content-plus-window fallback.
- 2026-07-31 | MetaWearableAdapter's server-side contract **terminates at the companion app**, emitting device-agnostic domain events | DAT has no server API and no cloud-to-glasses push — everything is phone-mediated over Bluetooth; identical events from glasses, companion app, web inbox or simulator are what make the simulator honest | Meta shipping a server-side API, which does not exist today.
- 2026-07-31 | Native companion app is **out of the TS monorepo's vertical slice**; glasses leg proven through simulator + web inbox | DAT is native iOS/Android only (no React Native), and we have no Meta account, no hardware, and no Xcode | any of those three arriving, at which point the spike's device half runs for real.
- 2026-07-31 | Escalation requires **positive delivery confirmation**; absent an ack, degrade push → web inbox → honest client deferral | background *initiation* of glasses audio is unproven (architecture.md §3.3), and CLAUDE.md forbids ever treating silence as a founder answer | nothing — this holds even if the glasses path proves fully reliable.
- 2026-07-31 | Supabase RLS membership via a **`security definer` lookup function**, not JWT `app_metadata` claims | Supabase docs state plainly that "a JWT is not always fresh"; org membership can change mid-session and stale claims would silently mis-scope tenant data | membership becoming immutable per session, which it isn't.
- 2026-07-31 | Realtime channels topic-shaped `org:<organization_id>` with private channels + RLS on `realtime.messages` | reuses the same membership tables as row RLS, so realtime authorization can't drift from row authorization | none; `postgres_changes` stays acceptable at MVP scale but this is the documented scalable pattern.
- 2026-07-31 | **pgvector deferred until plain search is shown insufficient** on the seed knowledge set, with the comparison logged either way | CLAUDE.md scopes pgvector to "where semantic retrieval actually improves knowledge search" — that's a measurement, not an assumption | seed-set retrieval measurably missing paraphrased questions, which is the likely outcome and fine to act on once shown.
